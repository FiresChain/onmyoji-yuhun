# Onmyoji Yuhun

阴阳师御魂规划与阵容分析网站。

## 本地开发

```bash
npm ci
npm run dev
```

生产构建：

```bash
npm run check
```

网站通过 R2 的版本指针与不可变快照读取公开场景和阵容数据，`https://api.fireschain.org` 提供编解码与已同意的数据收集。用户上传的御魂快照默认只在浏览器本地处理，不会随网站代码发布。

式神和御魂图片由 `https://onmyoji-assets.fireschain.org` 的 R2 资源域名提供；可用 `VITE_ASSET_BASE_URL` 覆盖该地址。

## 本地诊断双码覆盖

使用私有诊断导出中的快照、规则和阵容计算结果，对比不同允许影响比例：

```bash
node --import tsx scripts/diagnose-plan-impact.ts /path/to/diagnostics.private.json 500 0 1 3 5
```

`500` 是预期空位，后续数字是允许影响百分比。脚本只在本地计算并输出汇总，
校验强化规则等严格保护项、去重后的影响额度和每码 60 组上限；新增规则不得改变预置方案的历史捞回范围。
含策略优先级的诊断沿用保存的排序：优先级决定让步顺序，百分比限制所有策略的让步总量。
预置规则原样保留，包括等级、星级和历史捞回条件；优化只追加针对未覆盖御魂的规则。
不要提交诊断文件或账号派生输出。

## 请求与用量边界

- 同一正文的并发编解码请求共用一个在途请求；20 秒超时，收到 `429` 后遵守 `Retry-After`，不自动重试。
- D/E 生成使用编码接口对实际输出码回解得到的 `share`，继续校验 ID、方案条件和安全门禁；每码从两次 API 调用减为一次，导入外部码仍调用解码接口。
- 旧阵容检查补全逐条执行，请求之间至少间隔 3 秒，兼顾现有 WAF 的 5 次/10 秒规则；失败或离开页面后停止剩余任务。失败目标仍可手动打开重试。
- 关卡读取合并并发请求，同一时间戳快照在当前页面会话内复用；再次进入仍读取版本指针，指针变化后加载新快照。
  只缓存标准不可变快照 URL，开发环境自定义可变 URL 不复用，失败请求不会永久缓存。
- 已同意的数据收集仍然发送，10 秒超时，不做后台重试或新增限流计数写库。
